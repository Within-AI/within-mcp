How to read this

  • Bands show who does the work. Left to right is the order of the work; systems are rails at the bottom that steps read from and write to.
  • Three performer bands: Analyst (Offshore desk, top) - Agent (read-only, middle) - ERP (clearing) (bottom, the system rail). The Agent mediates. read_access edges flow down from a step to a System rail; handoff edges flow up from Agent to Analyst carrying the briefing; the one inbound edge (10-in) flows down from Analyst to Agent carrying the analyst-supplied company-code scope; escalation (GATED) edges are the deliberately non-default escalate-don't-act paths, drawn dashed coral. Every write edge originates in the Analyst lane and targets a System surface (ERP line-item app). The System lane holds passive ERP (clearing) rails and one preserved result; it performs nothing the analyst did not initiate.
  • recommend-then-review. The agent reads permitted ERP (clearing) surfaces, groups candidate items, recommends CANCELLATION where supported, triages exceptions, packages evidence, and Escalates. The analyst validates or overrides every recommendation, holds every clearing decision, and performs every ERP line-item app/ERP (clearing) write. No agent-taken authoritative decision exists; the two decision diamonds are Analyst-lane review seams.
  • The V3 agent is intended to hold read-only entitlement to ERP (clearing) open-item tables (header and line-item tables or equivalent) and the Additional Log surface, and to write nowhere. Production feasibility, entitlement scope, schema, and access method remain More information required (WWSNTK-7). In the Sandbox a synthetic adapter maps into a provisional clearing snapshot; production ERP (clearing) must map into the same snapshot shape. Sandbox read adapters never establish production ERP (clearing) access.
  • The agent writes nowhere - zero writes to client systems of record (ERP (clearing) / ERP line-item app / Excel). No write edge originates from an Agent-lane node. The agent touches ERP (clearing) only through read_access and leaves its lane only through a handoff (the briefing) or an escalation. The analyst performs every ERP line-item app/ERP (clearing) write; that today-state is Observed, the agent-zero-write boundary is an Assumed design invariant / ratified control (no V3 agent exists to observe). A single agent-originated write is a critical violation.
  • GATED in the DAG marks the deliberately non-default escalate-don't-act path - it is a path disposition, not a fourth epistemic grade, and in the DAG it appears only on edges. It is rendered here as the house escalation edge (edge kind 'escalation', dashed coral). The underlying epistemic state of those edges is Assumed (the DAG writes them '[GATED; Assumed control grounded by unresolved evidence]'), carried in evidence_state. No new legend term is introduced.
  • Zero-write: The agent writes nowhere - zero writes to client systems of record (ERP (clearing) / ERP line-item app / Excel). Assumed design invariant / ratified control; the Analyst performing every ERP line-item app/ERP (clearing) write today is Observed.
  • Person's decision and action: The Analyst validates or overrides every recommendation and performs every ERP line-item app/ERP (clearing) write. Observed.
  • Escalation-first: Insufficient evidence always Escalates; it never defaults a label. Assumed control, grounded by unresolved evidence states.
  • Primary-path policy only: CANCELLATION is the client-ratified first-pass policy for supported primary-path groups; not an evidence-derived selection rule. Assumed policy.
  • Exception limitation: The exception seam is triage plus evidence packaging only. No exception-to-label recommendation appears in this DAG. Observed boundary / Assumed Agent control.
  • Correction-path limitation: Correction-path routing remains Analyst-owned or belongs to a separate PRD. Needs more information.
  • No false certainty: Evidence state is preserved on each node and edge; GATED paths remain visibly non-default. Assumed design requirement.
  • Triage category blocked_period: Posting-period-closed message; defer / follow-up by a person signal. Evidence: Message and deferral Observed; accountable owner and return timing needs more information (WWSNTK-6). Boundary: No period-opening action or routing decision.
  • Triage category selection_rework_required: 'No G/L account documents selected' / empty-selection signal. Evidence: Observed Boundary: No selection-rule invention; package the criteria context for Analyst review.
  • Triage category policy_review_required: AC07 / CUSTOMER withholding-tax message. Evidence: Message presence Observed; permitted action and owner needs more information (WWSNTK-4). Boundary: Surface for review; do not assert tax policy or an Item Text label.
  • Triage category non_pair_residue: Item(s) without a supported offsetting-pair outcome. Evidence: Needs more information as an exception-routing category. Boundary: Surface only; the agent does not own correction-path routing.
  • Triage category unclassified_exception: Any other message or condition not covered above. Evidence: Needs more information Boundary: Escalate with available evidence; no default classification or label.
  • Excluded triage category counterpart_missing: Deliberately excluded: it has no evidence anchor.
  • Out of scope: Agent writes of any kind. (Observed exclusion)
  • Out of scope: An exception-message-to-label selection rule. (Needs more information; GATED)

  • Out of scope: Any label vocabulary beyond the CANCELLATION first-pass policy. (Needs more information)
